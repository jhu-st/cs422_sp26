Delta Debugging

Delta Debugging (dd) follows on the idea of simplification for automatically minimizing a failing input. In other words, the dd algorithm is a recursive binary-search-like procedure that takes in a large failing input and it finds the smallest subset of it that still causes the same failure.

dd algorithm:#

  • Let c be a failing input configuration (sequence of individual inputs)
  • test(c) runs a test on c with possible outcome PASS or FAIL
  • n is the number of chunks to split c into (initially n = 2). We will remove one chunk at the time and test the remaining input.
ddMin(c, n) :
1. If: |c| = 1 return c
// Otherwise, systematically remove one chunk 𝒄𝒊 at the
// time. Test the remaining input c \ 𝒄𝒊 :
2. If there exist some 𝒄𝒊 such that test(c \ 𝒄𝒊 ) = FAIL
return ddMin(c \ 𝒄𝒊 , max(n-1, 2))
3. Else if: n < |c|
return ddMin(c, min(2n, |c|))
4. Else: // (can’t split into smaller chunks)
return c

Example#

Assume, we are testing the following function:

// compute the checksum of an integer array
public static int checkSum(int[] a)

The function implementation is faulty: it gives wrong result, whenever a contains two identical consecutive numbers, but let us pretend we don`t know that yet. All we know is that the function fails on the following input:

{1, 3, 5, 3, 9, 17, 44, 3, 6, 1, 1, 0, 44, 1, 44, 0}

Delta Debugging#

Delta Debugging is an approach to isolate failure causes by narrowing down differences (deltas) between runs. Delta Debugging can be applied to various types of inputs such as:

  • failure-inducing program input, e.g., HTML page
  • failure-inducing user interactions e.g., the key/mouse strokes that make a program crash
  • failure-inducing changes to the program code, e.g., after a failing regression test
  • etc.
DD mindset

Delta Debugging gives an alternate mindset to the debugging problem. Normally, when something does not work as expected (i.e., you have a “failure”), you would naturally think: “hmmm, what’s wrong here?”. Delta Debugging takes an alternate approach by fist asking: “what is NOT wrong here?”, or in other words, “what is irrelevant here?”. This helps to exclude those irrelevant parts first and put them aside to simplify/minimize things into a more manageable size.
